# Beads backlog audit — 2026-09-07

Source baseline: `4ef2e902` on `master`. This audit changes issue metadata and documentation; it implements no runtime feature.

Reviewed all 69 active issues and cross-checked the 68 closed records as historical context. Previously closed dispositions and closure reasons are retained. A subsequent review cleared workstation source-location metadata from the exported records. Each active issue has a disposition below; implementation-ready means its scope and entry points are specified and Beads has no unresolved local blocker. It does not claim a fresh runtime reproduction or test pass.

## Result

- Closed 15 duplicate records, including the imported monorepo tree, with explicit canonical owners.
- Closed nine issues whose original defect or missing behavior is already addressed in current source.
- Rewrote 45 remaining contracts with current evidence, implementation scope, source entry points and acceptance criteria.
- Deferred the nine Jury cutover records to match the authoritative upstream plan.
- Added the missing dependency from scoped freshness gate integration to targeted retry composition; related-only links distinguish adjacent work without falsely blocking independent fixes.

The P1 recommendation before this audit was based on tracker state. `jig-sh-cdi` is already implemented. `jig-sh-mdl` already handles valid failed-check JSON; its remaining focused regression work is now P2. `jig-sh-qh4` remains an active P1.

## Material contract corrections

- Current authored repository contract is v7. Source migration `.1.2` and native file-budget `.8` are complete; future tasks must preserve them.
- Scoped freshness `.4.3` now depends on `jig-sh-qh4` and preserves original per-target retry provenance. It no longer requires one complete run for profile evidence.
- The legacy loop cache crash task is limited to the remaining cache-mode path; Git-backed protected state already uses durable publication.
- The draft/fork safety task now focuses on missing draft state; exact same-repository checks already exist.
- Frontend install-locking layout work targets the current native 800-line policy, replacing the retired Rust LOC rule.
- Passing isolated tests do not close unresolved flakes. Remaining flake contracts require a current controlled reproduction, explicit synchronization and preserved failure oracles.
