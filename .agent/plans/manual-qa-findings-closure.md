## Surprises & Discoveries

- A successful negative-PGID `SIGKILL` is delivery to the members visible during that kernel group iteration, not a durable barrier against a member concurrently entering or becoming visible in the still-pinned group. The source-current frontend-preflight regression passed three repetitions and failed on the fourth; an independent macOS harness reproduced a live, reparented, same-PGID sleeper 23/100 times after the one-shot kill. The identical one-shot-signal/poll-only shape exists in doctor/preflight, dev-app, and vault supervisors. Re-signal only while an unreaped exact child pins the PGID; a direct proxy stop that owns only a numeric PID must remain one-shot to avoid targeting a recycled process.
- The rendered-name formatter problem also crosses a separately configurable boundary: `sqlx::migrate!("<migration path>").run(...)` is rewritten for intermediate custom migration-path lengths even when the repository name is short. A normal short PostgreSQL render independently rewrites `Ok(Self { pool, })` to its singleton form. Exact Rust-file rendering, not one default workspace, must therefore cover every database branch and migration-path substitution.
- A 242-byte normalized repository stem fits the longest generated source directory but does not produce a usable Rust workspace: Cargo's `lib<stem>_test_support-<hash>.rmeta` artifact first exceeds the 255-byte component ceiling at stem length 217. The supported normalized stem boundary is 216, validated before destination mutation. Separately, the generated direct-Vite fallback puts the repository stem in one DNS label, which stops resolving above 63 bytes; retain long supported package names by using the dev proxy's existing bounded-prefix label rather than silently accepting a broken fallback origin or changing bookmark identity.
- POSIX defines signal ownership at delivery, but it does not give a multi-threaded process a user-space barrier between kernel disposition selection and the callback's first instruction. A doctor callback delayed before its first atomic claim can therefore enter after one clean session retires and another begins. Treat callback entry as the ownership linearization point: it joins the then-active generation and is protected by that generation's in-flight count, or takes the fail-closed idle path. An isolated regression pauses before the claim, retires generation one, starts generation two, and proves cancellation, restored-disposition redelivery, and generation-three reuse.
- Rustfmt's dynamic line-width transitions are non-monotonic for generated identifiers and string literals: a 24-character module name already rewrites the API signature/filter, mid-length names rewrite calls/imports across API and test-support crates, and very long unbreakable strings stop wrapping while dynamic type signatures still do. The existing normal-name and one 120-character admin render do not run a formatter-stability matrix over the owned Rust source surface, so a valid 31-character npm/SQLite repository fails its immediate `jig.fmt_check`.
- npm can hoist every dependency into the root workspace and leave a member `node_modules` absent when its receipt is stamped. TypeScript, Vite, Vitest, and Playwright then create only the exact top-level cache directories the proof intentionally ignores. The child walk omits their bytes, but the enclosing root is still encoded as `node-modules-present` instead of its prior `node-modules-absent`, invalidating readiness after ordinary generated commands. An ignored-only real root must normalize to the existing absent encoding while unknown entries and type replacements remain attested.
- npm gives `npm-shrinkwrap.json` authority over `package-lock.json`, including when both exist, but the generated checker, adoption inference, workflow filters, cache inputs, and receipt selection recognize only `package-lock.json`. Ambient `NODE_ENV=production` or `NPM_CONFIG_OMIT` can also make a successful bare npm install permanently attest a dependency tree without its development, optional, or peer classes; explicit repeated `--include` flags override those omissions in the pinned npm runtime.
- Bash imports option and trace controls before executing a script. In a Jig-owned Bash probe, inherited `SHELLOPTS=xtrace` plus a command-substituting `PS4` can execute code on the first command, `verbose` can leak source, `BASH_XTRACEFD` can corrupt a structured output channel, and `BASHOPTS` changes parsing state. Exported-function keys must be matched as raw `OsStr` bytes: Bash imports `BASH_FUNC_\xff%%`, while the current UTF-8-only sanitizer misses it.
- A full procfs scan can cross its caller's deadline after the last checked stat operation. Doctor and vault can then accept a late live/empty result, while proxy TERM and SIGKILL helpers reconstruct fresh deadlines when the direct leader exits. Cleanup phase deadlines must be absolute values threaded through every state transition, iterator boundary, fallback classification, result acceptance, and capped sleep.
- A regression that sets `SHELLOPTS=xtrace` and a command-substituting `PS4` in the Rust test process can trigger its marker from an unrelated parallel Bash spawn even when the production command is correctly sanitized. Inject hostile variables directly into the exact `Command`, sanitize that command, and separately assert the production command plan's removals; never publish process-global shell poison during a parallel suite.
